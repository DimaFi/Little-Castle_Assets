# Модульная каменная стена — v002, объёмная кладка

Рабочая визуальная переработка после отклонения пользователем v001 за плоскую
кладку и плохую фактуру. Не опубликованный релиз и не результат Unity Play Mode.

## Что изменилось

Камни теперь отдельные замкнутые объёмы внутри объединённого mesh: четыре
перевязанных ряда стены, неодинаковые выступы, скруглённые и неровные грани,
настоящие углублённые швы. Внутренний сердечник закрывает сквозные щели.
LOD0 имеет двухсегментные фаски, LOD1 — односегментные, LOD2 — простые блоки
без фасок, но с сохранением рядов и рисунка швов (не гладкую плиту).
Текстурный displacement не используется. Без текстур результат виден в
`Preview/QA_Clay_Closeup.png`.

Первую попытку наложить маленькие участки исходной кладки отбросили: она
сильно увеличивала размытую фактуру. Для v002 встроенным image_gen создана
отдельная общая текстура `Textures/T_WallStoneSurface_A_BaseColor.png` без
нарисованных швов. Промпт и происхождение — `Textures/generation-prompt.txt`.
Плотность UV всех каменных поверхностей — 0.8 UV/м; один материал на mesh.
Нет уникальных текстур на сегмент, процедурных Blender-only шейдеров или
зависимости от генератора в игре. Roughness = 0.9, normal map отсутствует:
крупный рельеф полностью геометрический.

Исходные `StoneWall_A_*` пользователя сохранены побайтно в `Textures/`.
Они остаются альтернативным материалом/референсом, но НЕ назначены новой
кладке. Их Normal/AO/Height нельзя накладывать поверх новых камней: рисунок
швов уже не совпадает с геометрией. Нужные Unity-параметры однозначно заданы
в `Textures/material-bindings.json`.

## Модели и технический контракт

| FBX | Размер Unity X × Y × Z, м |
|---|---|
| SM_Wall_Stone_2m_A | 0.60 × 1.40 × 2.00 |
| SM_Wall_Stone_1m_A | 0.60 × 1.40 × 1.00 |
| SM_Wall_Stone_Pillar_A | 0.70 × 1.60 × 0.70 |
| SM_Wall_Stone_End_A | 0.60 × 1.40 × 0.60 |
| SM_Wall_Banner_Cloth_A | 0.36 × 0.55, глубина < 0.03 |
| SM_Wall_Banner_Bracket_A | 0.42 × 0.065 × 0.047 |

Исходник — `Wall_Stone_Modular.blend`, шесть экспортов — `Meshes/`.
В каждом FBX три mesh `*_LOD0/1/2`, показывать только один через LODGroup.
Сводка измерений и числа треугольников — `QA/geometry_report.json`.
Корни identity, метры, Y вверх, длина стены Z; pivot камня в нижнем центре.
Blender использует Z вверх; экспорт преобразует U(x,y,z) = B(x,z,-y).
Не поворачивать FBX дополнительно на 90° вручную.

Четыре каменные модели содержат UCX box-прокси. Unity автоматически не
превращает их в коллизию: создать BoxCollider, убрать renderer прокси.
У торцов стены оставлена спокойная полоса 0.10 м с небольшим сужением для
перекрытия. Углы и период опор задаёт игровой код, не геометрия.
Опорный столб — не игровая башня лучников.

## Флаги

Полотно и нейтральное крепление — отдельные модели. Полотно белое, без
зафиксированного синего цвета/герба. UV0 занимает 0..1, верх v=1; передняя
сторона local +Z, pivot в верхнем центре, обратная сторона читаемая.
На 2м-модуле и столбе есть `BannerAnchor_XPlus` / `BannerAnchor_XMinus`.
Полотно и крепление присоединяются с local identity. PNG с alpha нужно
композить поверх выбранного цвета фона, чтобы цвет не тонировал сам герб.
Редактор дизайна и сохранение по ID здесь не реализуются. Тестовые цветные
материалы и PNG в QA не входят в экспортированное полотно.

## Проверки и продолжение

`build_wall_kit.py` запускать Blender 4.4 в background; затем
`validate_wall_kit.py`. Последний читает бинарные FBX, проверяет оси,
масштаб, габариты, UV, локаторы и обратный импорт, сверяет с исходным blend.
`-- --previews=Stone_and_Banner_Closeup.png` ограничивает рендеры генератора.
Генератор перезаписывает только собственные WIP-результаты внутри v002.

Исходные коллекции скрыты в viewport у начала координат. Галерея, камера и
свет — отдельная `90_PREVIEW_ONLY_DO_NOT_EXPORT`; это не часть FBX.

В Unity ничего не импортировано. Публиковать в `Releases/` только после
визуальной приёмки, затем копировать конкретную версию в Unity. Не
импортировать рабочую папку Source напрямую. v001 сохранена для сравнения.

Рендер сборки не проверяет runtime: код пока требует интеграции selector
1м, end cap и флагов. Шаг центров = totalLength/ceil(totalLength/spacing),
то есть 1.92 м — верхний предел, а не гарантированный шаг. У башен удаление
по центрам сегментов может оставлять щели; Sharp-точки не ставят столб
автоматически. Нужны отдельные проверки в Unity после приёмки внешнего вида.
