# Модульная каменная стена A — v001

> Историческая версия: пользователь отклонил внешний вид за плоскую кладку
> и плохую фактуру. Не публиковать и не импортировать. Продолжение — `../v002/`.
> Нижеследующие измерения относятся только к v001 и не являются её приёмкой.

Создан комплект из шести отдельных моделей. Исходник —
[Wall_Stone_Modular.blend](Wall_Stone_Modular.blend), экспорт — `Meshes/`,
проверки — `QA/`, изображения — `Preview/`.

Материал выбран пользователем: `CozySettlement/Mat/StoneWall_A_Unity`.
Его PNG скопированы без изменения байтов. Один общий материал
`M_Wall_Stone_Shared`; плотность UV — 0.5 UV/м (один тайл на 2 метра).
На плоскостях кладки UV непрерывные, рельеф согласован с Height-картой.
Height использована только в авторинге для небольшого статичного рельефа;
Unity не требуется runtime displacement. Силуэт зубцов, колпаков и поясов
сделан геометрией. BaseColor, Normal (сила 0.12), Roughness подключены
в Blender; AO и Height также сохранены для интегратора.

|---|---|---|
| SM_Wall_Stone_2m_A | 0.60 × 1.40 × 2.00 | 3488 / 1508 / 212 |

| SM_Wall_Banner_Cloth_A | 0.36 × 0.55, глубина менее 0.03 | 384 / 96 / 24 |
| SM_Wall_Banner_Bracket_A | 0.42 × 0.065 × 0.047 | 300 / 60 / 36 |

Каждый FBX содержит свой корень, три именованных `*_LOD0/1/2` и один
простой `UCX_*` box-прокси у каменных моделей (12 треугольников).
В сборке показывать только один LOD: геометрия всех трёх не должна
рисоваться одновременно. Все корни FBX identity, единицы — метры.

В Blender используется привычная ось Z вверх. При экспорте выполняется
преобразование `Unity(x,y,z) = Blender(x,z,-y)`. В FBX вертикаль Y, длина
стены Z. Это проверяет скрипт, читающий реальные бинарные координаты FBX.
Не вращать готовый FBX повторно на 90 градусов вручную.

В последних 0.10 м торцы плавно сужены примерно на 1 см с каждой стороны.
Это технический припуск для перекрытия: он устраняет совпадение плоских
поверхностей при установке с шагом 1.92 м. Номинальная длина и максимальная
ширина модуля сохранены. Тонкий стык материала при близком осмотре возможен;
точное совпадение тайлов на произвольной кривой не зашито в модель.

В исходнике все шесть исходных коллекций находятся в начале координат и
скрыты в viewport; их можно раскрыть в Outliner. Коллекция
`90_PREVIEW_ONLY_DO_NOT_EXPORT` — отдельная галерея из связанных копий,
камера, свет и фон. F12 рендерит галерею. Исходные объекты редактируемы;
геометрия не содержит скелетов или зависимости от генератора во время игры.

## Флаги

Полотно экспортируется белым, без герба, фотографии или зашитого цвета.
Передняя сторона — local +Z; pivot — верхний центр. Есть обратная поверхность
с отдельными нормалями и UV, чтобы изображение читалось с обеих сторон при
обычном backface culling. Размер и UV сохраняются между LOD.

UV0: прямоугольник 0..1, верх изображения соответствует верху полотна.
Прямоугольная фотография должна сохранять пропорции: будущий compositor
выбирает fit/contain или crop, а не растягивает квадрат на весь флаг.

На 2м-стене и столбе экспортированы точные `BannerAnchor_XPlus` и
`BannerAnchor_XMinus` (без `.001`). Их local +Z направлен наружу, local +Y
вверх. Полотно и крепление ставятся дочерними объектами с local identity.
Флаг не создаёт игровых коллизий. Точки крепления не являются wall sockets.

`QA_Player_Colours.png` показывает четыре возможных цвета на одном mesh.
`QA_Banner_PNG_LODs.png` проверяет замену изображения, ориентацию и LOD
на асимметричной тестовой PNG. Эти тестовые материалы/картинки не назначены
экспортированному полотну и не являются предложенными гербами игрока.

Будущая окраска ткани и PNG-эмблема должны быть независимы. Для текущего
шейдера практичный вариант: один раз скомпоновать фон + PNG с alpha в
непрозрачную текстуру на дизайн, затем использовать `_MainTex` и белый
`_Color`. Тогда красный фон не перекрасит белый или фотографический герб.
Прозрачность PNG-эмблемы сама по себе не требует alpha-clipped ткани:
прозрачные места показывают цвет фона. Alpha clipping понадобится только
для дырок/вырезов в самом полотне. Шейдер/редактор гербов пока не создавались.

## Сборка и проверки

Из `v001`:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 4.4\blender.exe' --background --factory-startup -t 6 --python-exit-code 1 --python .\build_wall_kit.py
& 'C:\Program Files\Blender Foundation\Blender 4.4\blender.exe' --background --factory-startup --python-exit-code 1 --python .\validate_wall_kit.py
```

Генератор детерминирован, повторный запуск заменяет только собственные
WIP-файлы в `v001`. После публикации исправления делать в новой версии.
`-- --previews=Kit_Overview.png` ограничивает перечень повторных рендеров;
экспорт и сохранение исходника выполняются всегда.

QA проверяет реальные FBX: метры/Y-up, identity transforms, габариты,
локаторы, LOD, UV без вырожденных треугольников, один материал на mesh,
повторный импорт, повторное открытие `.blend` и SHA-256 исходных карт.
Тестовые сборки: прямая, смешанная 2м/1м, дуга с шагом угла 5°, столб на 90°.

## Передача в Unity

Библиотека ассетов имеет отдельные правила: исходник остаётся здесь,
Unity получает только проверенную копию `Releases/Wall_Stone_Modular/v001`.
Целевая папка — `Little-Castle/Assets/_Game/Art/Imported/Wall_Stone_Modular/v001`.
Игровой проект автоматически не изменяется.

Интегратор создаёт `LODGroup`, общие материалы на LC Stylized Lit,
`BoxCollider` из параметров прокси и `WallPlacementDefinition`. `UCX_` —
соглашение имён для прокси, а не встроенный в Unity автоимпорт коллизии:
прокси-renderer нужно убрать после создания BoxCollider.

`Textures/material-bindings.json` описывает карты и import settings.
Для флага материал белый; создавать клон материала на каждый сегмент не нужно.
Разные текстуры могут разбивать batching: общий материал сам по себе не
гарантирует GPU instancing для всех дизайнов; атлас/texture array — будущая
оптимизация по результатам профилирования.

Проверка Unity/Play Mode ещё не выполнялась. Существующий runtime требует
отдельной интеграции: selector 1м, end cap, расстановка баннеров. Кроме того,
генератор сейчас распределяет центры как `totalLength/ceil(totalLength/spacing)`,
поэтому 1.92 м — максимум шага для 2м, а не всегда фактический шаг. Удаление
секций рядом с башней основано на расстоянии центра, не на обрезке по сокетам:
нужно проверить зазоры и фазу расстановки башен при интеграции. Sharp-точка
не ставит столб автоматически, tangent sampling около угла может повернуть
соседний модуль диагонально. Рендер QA показывает геометрическую совместимость
ручной сборки, а не доказательство отсутствия этих ограничений в коде.
